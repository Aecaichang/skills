# คู่มือผู้ใช้สำหรับส่งลูกค้า

เขียนจากสิ่งที่เห็นบนหน้าจอเท่านั้น ผู้อ่านคือผู้ใช้งานทั่วไป ไม่ใช่นักพัฒนา
เรื่องภายใน (spec, บั๊ก, endpoint, ชื่อไฟล์, id ภายใน) ห้ามปนในคู่มือ
ทำ **ทีละเมนูให้จบ** แล้วค่อยรวมเล่มทีหลัง แยกเล่มตามกลุ่มผู้ใช้ เช่น เล่มผู้ใช้ทั่วไป เล่มผู้ดูแลระบบ

## เก็บต้นฉบับ

- เขียนเป็น Markdown 1 เมนู = 1 ไฟล์ เลขนำหน้าชื่อไฟล์คุมลำดับ เว้นช่วง 10 เพื่อแทรกทีหลัง
- ต้นฉบับ Markdown คือแหล่งเดียว ไฟล์ Word/PDF เป็นผลผลิต ห้ามแก้ใน Word แล้วหวังให้ย้อนกลับ
- ลูกค้าคอมเมนต์มา แก้ที่ต้นฉบับ แล้วสร้างไฟล์ใหม่ทับ
- แก้ทีละจุดด้วยการแทนข้อความตรงๆ ไม่เขียนไฟล์ใหม่ทั้งไฟล์ ใช้ version control เพื่อดูว่าแต่ละรอบเปลี่ยนอะไร
- ลำดับในเล่มเรียงตามที่ผู้ใช้ทำจริง: ตั้งค่า, ยื่นคำขอ, อนุมัติ, ดูรายงาน

## โครงหัวข้อ

| ระดับ | ความหมาย |
|---|---|
| `#` | โมดูลหรือบท ขึ้นหน้าใหม่ |
| `##` | เมนู |
| `###` | เรื่องในเมนู |
| `####` | แท็บหรือหน้าจอย่อย |

โครงต่อ 1 เมนู เล่าตามลำดับที่ผู้ใช้เจอจริง:

```
## <ชื่อเมนู>
 ภาพเต็มหน้าจอ (สะอาด ไม่มีกรอบ)
 เมนูนี้ใช้ทำอะไร 1 ประโยค
 ผู้ใช้งาน, สิทธิ์ที่ต้องมี, เส้นทางเมนู
 ### หน้าจอนี้ทำอะไรได้บ้าง    (ภาพรวม ถ้ามีแท็บแตกเป็น ####)
 ### ส่วนประกอบหน้าจอ         (เลขตรงกับกรอบแดงในภาพ)
 ### ขั้นตอน<ทำอะไร>          (1 งาน 1 หัวข้อ ทีละข้อ จบด้วยผลลัพธ์)
 ### ข้อมูลที่ต้องระบุ         (ตาราง: ชื่อฟิลด์ | ความหมาย | บังคับกรอก)
 ### ข้อควรระวัง              (เรื่องที่ทำพลาดแล้วเสียหาย หรือผลที่ไม่เห็นทันที)
```

หัวข้อที่เมนูไม่มี (เช่น ลบไม่ได้) ตัดทิ้งเลย อย่าเขียนว่า "ไม่มี"
ถ้าจะทำสไลด์อบรมจากต้นฉบับเดียวกัน ให้ 1 หัวข้อ `###` = 1 หน้าสไลด์ bullet สั้น 1 ข้อ 1 เรื่อง ไม่เกิน 5 ข้อ

## กติกาเขียน

- ทุกเมนูขึ้นต้นด้วยภาพหน้าจอก่อน แล้วค่อยเขียนคำอธิบาย
- **1 action ต่อ 1 ข้อ** เลขเรียงต่อเนื่อง ไม่ซ้อนเลขย่อย เส้นทางเมนูรวมเป็นข้อเดียว เช่น **เมนูแม่ › เมนูลูก › หน้า**
- ชื่อปุ่ม เมนู ช่องข้อมูล ข้อความแจ้งเตือน ใช้ **ตัวหนา** และคัดลอกจากหน้าจอเป๊ะ ห้ามแปลหรือสะกดเอง
- **ผลลัพธ์เป็นข้อสุดท้ายของลำดับ** ไม่ใช่ย่อหน้าห้อยท้าย เช่น ข้อ 5 "ระบบแจ้งเตือน **บันทึกข้อมูลเรียบร้อย** และรายการขึ้นสถานะ **รออนุมัติ**"
- ค่าที่เลือกได้ของ dropdown ลิสต์ให้ครบ ไม่เขียนว่า "เลือกประเภทที่ต้องการ"
- บอกสิทธิ์หรือกลุ่มผู้ใช้ที่ทำได้ทุกหัวข้อที่เป็นขั้นตอน
- ฟีเจอร์ที่ยังไม่เปิดใช้ เขียนว่า "อยู่ระหว่างทดสอบ" ไม่ระบุวัน
- ไม่ใช้ขีดยาว (— –) และจุดกลาง (·) ให้แยกเป็นประโยคใหม่ ใช้จุลภาค วงเล็บ หรือ bullet แทน
- ขนาดและฟอนต์คุมจากเทมเพลตเอกสารอย่างเดียว ห้ามใส่ขนาดหรือฟอนต์ในเนื้อหา
- เจอบั๊กระหว่างเขียนคู่มือ ให้จดแยกไว้ในบันทึกบั๊ก ไม่ลงคู่มือ ไม่เล่าว่าของเดิมพลาดยังไง

## ภาพหน้าจอ

- เก็บภาพจากเครื่องทดสอบเท่านั้น **ห้ามมีชื่อ รหัส อีเมล รูปพนักงานหรือลูกค้าจริง** ถ้าจำเป็นให้เบลอส่วนนั้น
- ขนาดหน้าต่างและภาษาของระบบให้เหมือนกันทุกภาพ
- **ภาพแรกสุดของหน้าเป็นภาพสะอาด ห้ามวงกรอบ** กรอบแดงและเลขใส่เฉพาะภาพในหัวข้อ ส่วนประกอบหน้าจอ แล้วอ้างเลขในคำอธิบาย
- ทุกภาพมีคำบรรยาย (caption) บอกว่าคือหน้าจออะไร ไม่เล่าวิธีใช้ซ้ำ ยาวไม่เกิน 1 บรรทัด
- ห้ามวางภาพหลายรูปติดกันโดยไม่มีเนื้อหาคั่น
- ตัดสินใจเองว่าตรงไหนต้องมีภาพ จุดที่ต้องมีเสมอ: หน้าจอหลักของเมนู, ฟอร์มกรอกข้อมูล, ข้อความแจ้งเตือนหรือ error ทุกแบบที่เขียนถึง, กล่องยืนยัน, ผลลัพธ์ที่หน้าจอเปลี่ยนหลังบันทึก
- ภาพกล่องข้อความครอปเฉพาะกล่อง ไม่เอาเต็มจอ
- วงกรอบชี้จุด: ใช้พิกัดจริงของ element ไม่กะจากภาพ วงเลขต้องไม่บังตัวหนังสือหรือปุ่ม กรอบไม่ทับกัน
- ภาพที่ครอป ให้ตัดที่ขอบคอลัมน์หรือขอบ element ไม่ตัดผ่านกลางข้อความ และเว้นขอบขาวพอให้วงเลขไม่โดนตัด
- ภาพที่ครอปแคบ ไม่ขยายเต็มหน้าจนเบลอ
- เปิดดูภาพด้วยตาครั้งเดียวตอนเขียน แล้วจดสิ่งที่เห็น (ชื่อคอลัมน์ ค่าใน dropdown ข้อความแจ้งเตือน) ลงต้นฉบับให้ครบ

## ไดอะแกรม

เรื่องที่มีลำดับขั้นตอนหรือสถานะ (การอนุมัติ, สถานะคำขอ) ใส่ไดอะแกรมเป็นรูปภาพใต้หัวข้อของเรื่องนั้น
ครอบคลุมทุกกิ่ง ไม่ใช่แค่เส้นทางปกติ ใช้ชื่อสถานะตรงกับที่เห็นบนหน้าจอ

## รวมเล่มและอัปเดต

- ทำทีละเมนูให้จบก่อน รวมเล่มตอนใกล้ส่ง
- บทที่ใช้ร่วมกัน (เช่น เข้าสู่ระบบ) ก๊อปไปทุกเล่ม และแก้ให้ตรงกันทุกที่เมื่อมีการเปลี่ยน
- เมนูใหม่แทรกด้วยเลขนำหน้าไฟล์ที่ว่าง ไม่ต้องเลื่อนไฟล์อื่น
- ระบบเปลี่ยน: แก้เฉพาะเมนูที่กระทบ เปลี่ยนภาพที่ล้าสมัย ตรวจว่าเมนูอื่นที่อ้างถึงไม่ขัดกัน แล้วเพิ่มแถวใน Revision sheet
- หน้าปกมี: ชื่อเอกสาร ชื่อลูกค้า ชื่อโครงการ เวอร์ชัน วันที่ และตารางประวัติการแก้ไข/การอนุมัติ มีสารบัญเสมอ
- รักษาความสอดคล้อง: คำเรียกเดียวกันใช้คำเดียวทั้งเล่ม (เช่น ไม่สลับ "ยกเลิก" กับ "ลบ" ถ้าเป็นปุ่มเดียวกัน)

## เช็คก่อนส่ง

- [ ] เปิดไฟล์ที่สร้างจริง ภาพไม่ล้นขอบ หัวข้อไม่ค้างท้ายหน้า ตารางไม่แตก สารบัญครบ
- [ ] ไม่มีข้อมูลบุคคลจริงในภาพและในข้อความ
- [ ] ไม่มีคำภายใน: ชื่อ branch, endpoint, path, ชื่อไฟล์, id ภายใน
- [ ] ทุกหัวข้อระบุสิทธิ์/กลุ่มผู้ใช้ ทุกภาพมีคำบรรยาย
- [ ] ขั้นตอนเลขเรียงถูก และทุกลำดับจบด้วยข้อผลลัพธ์
- [ ] ชื่อปุ่ม เมนู ข้อความแจ้งเตือน ตรงกับหน้าจอจริง (ตรวจด้วยการค้นข้อความ ไม่อ่านทั้งไฟล์)
- [ ] ปกถูกต้อง: ชื่อลูกค้า เวอร์ชัน วันที่
- [ ] ตรวจคำสะกดและไม่มีขีดยาว/จุดกลาง
- [ ] สไลด์ (ถ้ามี) ข้อความไม่ล้นกรอบ และหัวข้อครบทุกเมนู
